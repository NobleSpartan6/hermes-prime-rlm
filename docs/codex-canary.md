## Goal and host check

The disposable source repository contained only `greet(name)`. Hermes sent this
bounded goal through RPC stdin—not process argv:

```text
Add a farewell() function to app.py that returns a goodbye string, and document
both greet() and farewell() in README.md. Keep the change minimal.
```

Hermes supplied one recorded host check:

```text
python -c "import app; assert callable(app.greet) and callable(app.farewell)"
```

Future demo invocations add Python's `-B` switch so that this check does not
create `__pycache__`. This canary predates that polish fix, and its receipt
honestly records the generated bytecode path as untracked evidence.

## Candidate evidence

Prime changed `app.py` from:

```python
def greet(name):
    return f'Hello, {name}!'
```

to:

```python
def greet(name):
    return f'Hello, {name}!'


def farewell(name):
    return f'Goodbye, {name}!'
```

It also documented both functions and created unit tests. Those model-created
tests are useful candidate evidence, but the receipt's `VERIFIED` status comes
only from the separately executed Hermes-hosted `import-check`.

## What `VERIFIED` does not mean

The canonical receipt explicitly retains:

```text
authenticity_status          UNSIGNED
candidate_status             UNQUIESCED
candidate_stability          unknown
integrity_status             RECORDED_NOT_REVALIDATED
acceptance_status            PENDING
candidate_may_have_partial_changes  true
```

The detached worktree is edit isolation, not a security sandbox. Prime and the
plugin run with the same user authority. The result proves that the recorded
host command exited zero against the recorded candidate; it does not prove
semantic correctness, independent custody, process quiescence, or acceptance.
